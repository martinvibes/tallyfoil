# Tallyfoil — Product Spec

## 1. Pitch
**Tallyfoil finds what your vendors overcharged you, proves it, and drafts the email to get it back.**

Medieval treasuries recorded a debt on a notched stick, split it lengthwise, and gave
each side half. If anyone altered the record, the halves no longer matched. You hold
your half of every deal (the contract, the order form, your usage logs). Tallyfoil
checks it against every bill the vendor sends.

## 2. Problem
- Nobody compares every invoice to the contract. Overcharges (price creep above the
  renewal cap, seats beyond the license, duplicate invoices, usage billed above what
  was logged) run for months.
- AI/API bills are worse: metered, opaque, and hard to reconcile against usage exports.
- Existing tools ask you to trust a black box. Finance people need proof they can send.

## 3. Users
Primary: ops/finance lead at a 20–500 person company paying for many SaaS + AI vendors.
Demo persona: **Ada, Head of Operations at Kestrel Labs** (fictional customer in the sample set).

## 4. Core loop (this is what the demo shows)
1. **Upload** a vendor's contract + invoices (+ usage export for AI vendors), or click
   **Load sample audit**.
2. **Agent reads.** In chat you watch it read each document and record terms and bill
   lines. The Terms table and Bills table fill live in the UI. Every value has an
   evidence chip.
3. **Code audits.** `run-audit` runs the deterministic engine. Findings stream in; the
   big **Recoverable** number counts up; **At risk** shows upcoming deadlines.
4. **You check the proof.** Click a finding → the Evidence view shows the two halves
   (bill quote vs contract/usage quote) with highlights and the arithmetic.
5. **You steer.** Accept, or reject with a reason ("we approved 48 seats by email on
   28 March"). The agent turns the reason into a vendor rule, re-runs, and the totals
   change in front of you. You can also edit any term directly.
6. **Dispute.** The agent drafts a dispute email per vendor. The evidence table and every
   amount are generated by code; the agent writes only the prose. You edit, approve,
   copy or open in your mail client. Tallyfoil never sends email itself.
7. **Watch.** A daily automation checks renewal notice deadlines and flags them.

## 5. Scope
### In (must ship)
- Vendors of two kinds: `seat_subscription` (SaaS) and `usage_metered` (AI/API)
- Upload PDF / TXT / CSV / pasted text; client-side text extraction
- Agent extraction with grounded evidence (contract terms, invoices, invoice lines)
- Deterministic usage-export parsing (CSV)
- Audit engine with 6 checks (ENGINE.md)
- Findings review (accept / reject with reason), vendor rules, live re-audit
- Evidence view (two halves + math)
- Dispute composer with number guard + approval
- Context awareness: navigation, selection, `view-screen`, `navigate`
- Renewal-watch scheduled automation
- Sample data loader + reset

### Stretch (only after must-ship is solid)
- `saveIfCurrent` edit-conflict handling on terms (FRAMEWORK_NOTES.md)
- MCP demo beat from Claude Code (`/mcp` is auto-mounted; just needs a demo)
- Export dispute packet as PDF
- Agent activity timeline panel

### Out
Email sending, bank/AP integrations, OCR of scanned PDFs, multi-currency, team sharing.

## 6. Data model (`server/db/schema.ts`)
All tables: `id text pk`, `owner_email text not null`, `created_at text default now()`.

| Table | Key columns |
|---|---|
| `vendors` | `name`, `kind` (`seat_subscription`\|`usage_metered`), `is_sample bool`, `currency` (always `USD` for now) |
| `documents` | `vendor_id`, `kind` (`contract`\|`amendment`\|`invoice`\|`usage_export`\|`note`), `name`, `text` (full extracted text), `sha256`, `is_sample`, `status` (`new`\|`read`\|`recorded`) |
| `terms` | `vendor_id`, `key` (enum below), `meter` (nullable, e.g. `halcyon-small input`), `value_num` (int, unit per key), `value_text`, `value_date`, `effective_from`, `effective_to`, `evidence_json`, `source` (`agent`\|`user`\|`rule`), `revision int` |
| `invoices` | `vendor_id`, `document_id`, `invoice_number`, `invoice_date`, `period_start`, `period_end`, `total_cents`, `evidence_json` |
| `invoice_lines` | `invoice_id`, `description`, `meter` (nullable), `quantity` (int: seats or tokens), `unit_price_micros` (int), `amount_cents`, `evidence_json` |
| `usage_totals` | `vendor_id`, `document_id`, `period_start`, `period_end`, `meter`, `quantity` (int) |
| `vendor_rules` | `vendor_id`, `type` (`override_term`\|`waive_check`), `payload_json`, `reason`, `created_by` (`user`\|`agent`), `active bool` |
| `audit_runs` | `scope` (vendor id or `all`), `engine_version`, `recoverable_cents`, `at_risk_cents`, `finding_count` |
| `findings` | `run_id`, `vendor_id`, `fingerprint` (stable), `check`, `severity` (`breach`\|`verify`\|`deadline`), `status` (`open`\|`accepted`\|`rejected`\|`explained`\|`cleared`), `title`, `explanation` (code template), `amount_cents`, `at_risk_cents`, `math_json`, `evidence_json`, `explained_by_rule_id`, `reject_reason`, `period_label` |
| `disputes` | `vendor_id`, `finding_ids_json`, `subject`, `body_md`, `evidence_table_md` (code-generated), `amount_cents`, `status` (`draft`\|`approved`), `revision int` |

Term keys and units:
`seat_price` (micros per seat per month) · `seat_cap` (seats) · `renewal_uplift_cap_bps`
(basis points, 5% = 500) · `term_start` / `term_end` (date) · `auto_renew` (0/1) ·
`notice_days` (days) · `meter_rate` (micros per 1M tokens, with `meter` set) ·
`billing_basis` (text: `usage_export` when usage is billed from the dashboard export).

`evidence_json` shape (used everywhere):
```json
{ "documentId": "doc_123", "fragments": [
  { "quote": "USD 24.00 per seat per month", "start": 412, "end": 441 } ] }
```
`start/end` are character offsets in `documents.text`, computed by the server matcher.

## 7. Actions (`actions/*.ts`)
Names are verb-noun (framework convention). ★ = in the agent's starter set (`deferLoading: false`).

### Reading
| Action | Purpose |
|---|---|
| ★ `view-screen` | `http:false`. Reads `navigation` + `selection` app-state, hydrates the current vendor/finding/document. Agent calls it before acting on "this". |
| ★ `get-overview` | Totals (recoverable, at risk), vendors with counts, latest run. GET. |
| ★ `get-vendor` | Terms, rules, invoices summary, findings for one vendor. GET. |
| ★ `read-document` | Returns document text with line numbers, paged (`fromLine`, `toLine`). GET. |
| `get-finding` | One finding with evidence fragments and math. GET. |

### Writing — ingestion
| Action | Purpose |
|---|---|
| `create-vendor` | `{name, kind}` |
| `add-document` | `{vendorId, kind, name, text, isSample?}`. UI calls it after client-side extraction; agent can call it with pasted text (e.g., an email). Dedupe by sha256. |
| `ingest-usage-export` | `{documentId}`. Deterministic CSV parse → `usage_totals` per meter and period. No AI. |
| ★ `record-terms` | Batch upsert terms, each with evidence fragments. Runs the evidence matcher. Rejects ungrounded values with `errorCode: "evidence_not_found"` or `"value_not_in_quote"` and lists which items failed so the agent can fix just those. |
| ★ `record-invoices` | Batch upsert invoices + lines with evidence. Same matcher. Validates `sum(lines) == total` (±1 cent) or fails with `errorCode: "lines_do_not_sum"`. |

### Writing — audit & review
| Action | Purpose |
|---|---|
| ★ `run-audit` | `{vendorId?}`. Calls `server/audit/engine.ts`, writes `audit_runs` + findings, preserves statuses by fingerprint. Returns totals and the delta vs the previous run. |
| ★ `review-finding` | `{findingIds: string[], decision: "accept"\|"reject", reason?}`. Reason required for reject. Accepts one row or a whole check group. |
| ★ `add-vendor-rule` | `{vendorId, type, payload, reason}`. Validates payload against the rule schema; re-runs the audit; returns the delta. |
| `remove-vendor-rule` | Deactivates a rule; re-runs the audit. |
| `update-term` | User correction `{termId, value, expectedRevision}` → `source:"user"`, bumps revision, re-runs the audit. (Stretch: `saveIfCurrent`.) |

### Writing — dispute
| Action | Purpose |
|---|---|
| ★ `draft-dispute` | `{vendorId, findingIds?, subject, intro, closing}`. Code builds `evidence_table_md` and total; agent supplies only prose. Runs the number guard on the prose. |
| `update-dispute` | User edits `{disputeId, subject?, intro?, closing?, expectedRevision}`; number guard again. |
| ★ `approve-dispute` | `needsApproval: true`. Marks approved; returns the full email text + a `mailto:` link. |

### Writing — app plumbing
| Action | Purpose |
|---|---|
| `load-sample-data` | Inserts the two sample vendors and their 17 documents from `seed/sample-documents.json` (text already extracted). Documents only — the agent still does the reading and recording live. The PDFs in `seed/sample-docs/` are for testing the upload path. |
| `reset-demo` | Deletes the current user's data. UI only (`agentTool: false`). |
| ★ `navigate` | Agent writes a one-shot `navigate` command (`{view, vendorId?, findingId?, documentId?}`). |

## 8. App-state contract
- `navigation`: `{ view: "home"|"vendor"|"finding"|"document"|"dispute", vendorId?, findingId?, documentId?, disputeId? }`
- `selection`: `{ kind: "finding"|"term"|"document-range", vendorId, findingId?, termId?, documentId?, start?, end?, label, capturedAt }`
- `navigate` (agent → UI one-shot): same shape as navigation, plus optional `path`.

`view-screen` must return: the navigation, the selection, and hydrated records
(vendor summary, the selected finding with evidence + math, or the open document's
visible lines).

## 9. Agent resources (copy from `app-agent/`)
- `AGENTS.md` → app root `AGENTS.md` (in-app agent instructions)
- `skills/audit-vendor`, `skills/learn-from-rejection`, `skills/write-dispute` →
  `.agents/skills/<name>/SKILL.md`
- `jobs/renewal-watch.md` → create as a Scheduled automation (see FRAMEWORK_NOTES.md)

## 10. Success criteria for the demo
- Sample audit from "Load sample" to all findings in under ~3 minutes of agent time.
- Engine output on the sample matches `seed/expected-findings.json` exactly:
  **$3,180.24 recoverable** before the rule; **$1,769.04** after the seat-cap rule;
  **$15,068.16 at risk** with notice due **2 Dec 2026**.
- Clicking any amount shows its math and both evidence halves.
- No crash, no spinner longer than 10 seconds without visible agent progress.
